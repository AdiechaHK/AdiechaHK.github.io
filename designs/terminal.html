36GB mongodb migration, liveweboccult · 2025
problemA production MongoDB at 250–300 concurrent connections (web services, batch jobs, edge devices) was starving the services sharing its host.
approachReplica-set promotion with a scripted cutover: quiesce writers → verify sync → promote secondary → rotate credentials → restart.
result10 seconds total downtime, plus one planned 20-minute window.
mongodblive-migrationreplica-sets
deduplication redesignimprowised · 2019–2022
problemAn eight-year-old platform assumed client-supplied IDs were stable. A client began emitting inconsistent identifiers for the same business; the assumption collapsed.
approachRather than rebuild, added an MD5 content hash over the business's identifying attributes as a fallback key — checked only when the primary ID misses. No existing API contract broken.
resultEliminated 95% of duplicate business records.

problem500K requests/day across up to 300 pods against a ~200GB database on rolling three-month retention, and the core scraper was the bottleneck.
approachRewrote it in Go and rolled the rewrite into the running system rather than staging a parallel cutover.
