Selected work

Face-recognition access control, deployed in Japan

WebOccult · 2025

Led engineering for a production access-control system on a customer site in Japan, integrating an in-house detection API with SESAME smart locks. The model was never the hard part. Making a vision system and third-party hardware agree on who may pass through a door — reliably, every day, in a building I did not control — was.

An agent that writes the reports nobody wanted to write

WebOccult · 2025

A Claude Code workflow pulling from Odoo and GitHub to assemble developer status reports and monthly client progress reports, with per-item evidence attached to every claim. The design question was never "can the model write this" — it was which judgments stay with a human. The agent gathers and drafts; people decide.

ResultStatus reports 30–45 min → ~5 min. Monthly client reports: a full working day → under 30 minutes, including revisions.

A care robot that had to answer fast enough to feel like a conversation

WebOccult · 2025

An elder-care robot prototype running a speech-to-text → LLM → text-to-speech loop. Latency is the entire product here. A pause that would pass unnoticed in a chat window is a broken conversation when someone is speaking aloud to a machine and waiting.

Moving 36GB of production data with the lights on

WebOccult · 2025

A production MongoDB — 250 to 300 concurrent connections from web services, batch jobs and edge devices — began starving the services sharing its host. I moved it onto dedicated infrastructure by replica-set promotion with a scripted cutover: quiesce writers, verify sync, promote the secondary, rotate credentials, restart.

DowntimeTen seconds in total, plus one planned twenty-minute window

When the client broke the contract our data model rested on

Improwised · 2019–2022

An eight-year-old scraping platform assumed client-supplied IDs were stable. A client began emitting inconsistent identifiers for the same business and the assumption collapsed underneath us. Rather than rebuild, I added an MD5 content hash over the business's identifying attributes as a fallback key, checked only when the primary ID misses — restoring integrity without breaking a single existing API contract.

ResultEliminated 95% of duplicate business records

500K requests a day, and a rewrite shipped into live traffic

Improwised · 2019–2022

Owned a scraping platform processing 500K requests per day across up to 300 pods against a ~200GB database on rolling three-month retention. Migrated the core scraper from Python to Go and rolled the rewrite into the running system.

Result10× execution-time improvement
